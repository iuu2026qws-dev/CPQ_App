## cpq-portal 登录"请求地址不存在"修复（08:05-08:08）

**根因**：
1. Vite 代理 `/api` → `http://localhost:8080` 缺少 `rewrite` → 请求 `/api/auth/login` 发送到后端变成 `/api/auth/login`，后端只有 `/auth/login` 报 404
2. `api/login.ts` 用原生 fetch 而非 axios request.ts，绕过了拦截器

**修复**：
- `vite.config.ts`：添加 `rewrite: (path) => path.replace(/^\/api/, '')`
- `api/login.ts`：改用 `request.post('/auth/login', ...)` axios 实例
- `utils/request.ts`：增加 `code !== 200` 错误抛出 + 401 自动清 token 跳登录 + isToken header 跳过认证头
- 验证：`curl http://localhost:3000/api/auth/login ...` → 200 + JWT token

## cpq-portal "认证失败，无法访问系统资源" 修复（08:10）

**根因**：缺少 `axios.defaults.headers['clientid']`。ruoyi-ui 在 request.ts 全局设置了 `clientid` 头，后端 Sa-Token 多终端认证校验需要此头。cpq-portal 只设置了 `Authorization` 但缺少 `clientid` → getInfo 返回 401。

**修复**：`request.ts` 增加 `axios.defaults.headers['clientid'] = clientId`
- 验证：带 `clientid` 头直接 curl `/system/user/getInfo` → code: 200, has user: True

## ProductCatalog 点击树节点右侧一直转圈修复（16:48）

**现象**：CPQ Portal 产品目录页点击左侧分类树的任意节点，右侧产品列表一直显示加载中的蓝圈，无数据返回。

   - `onAddBook`/`onAddEntry` 重置值：`effectiveDate: ''` → `effectiveDate: today()`
   - `submitBook`/`submitEntry`：包裹 `try/catch`，`catch` 中 `ElMessage.error(e?.message || '操作失败')`
   - `onDeleteBook`/`onDeleteEntry`：包裹 `try/catch`，`catch` 空（用户取消删除）

2. **`PriceRuleConfig.vue`**：同上模式 — `today()` + `effectiveDate: today()` + `submit` try/catch + `onDelete` try/catch

3. **`ChannelPriceList.vue`**：同上模式

4. **`VolumeTierConfig.vue`**：无日期字段，仅 `submit` + `onDelete` 加 try/catch

## 定价规则新增报错修复（18:43）

**问题**：PriceRuleConfig.vue 新增规则点确定时报「发生未知异常，请联系管理员」

**根因**：DDL `cpq_price_rule` 的 `condition_json` 和 `action_json` 是 MySQL JSON 类型列（`action_json NOT NULL`）。前端 `form` 初始值 `conditionJson: ''`、`actionJson: ''`，空字符串不是合法 JSON，MySQL 拒绝写入，JDBC 抛 RuntimeException → GlobalExceptionHandler 捕获 → 返回「发生未知异常」

**修复**：`PriceRuleConfig.vue` 的 `submit` 函数增加空值清理逻辑：
- `conditionJson` 为空 → 设为 `undefined`（JSON 序列化时字段不发送，后端 null，DEFAULT NULL 合法）
- `actionJson` 为空 → 设为 `'{}'`（空 JSON 对象，MySQL JSON 列接受且满足 NOT NULL）
- `expiryDate` 为空 → 设为 `undefined`（防止空字符串 Date 反序列化问题）

**教训**：MySQL JSON 类型列不接受空字符串，所有 JSON 列的表单字段初始化时应设 `undefined` 或有效 JSON 字符串，绝不能设 `''`

## 变体新增/编辑弹窗被表格展开行遮挡修复（19:52）

**问题**：产品目录页面展开行内的 VariantManager 组件，点击「新增变体」或「编辑」时，el-dialog 弹窗被 el-table 展开行裁剪，导致弹窗上半部分（表单区域）可见但下半部分（确定/取消按钮）被表格遮挡，无法完整操作。

**根因（两层）**：
1. `el-dialog` 默认渲染在组件所在 DOM 位置（即 el-table__expanded-cell 内部），Element Plus 的 `el-table__expanded-cell` 有隐式 `overflow: hidden` CSS，弹窗超出展开行高度的部分被裁剪
2. 即使弹窗有 `z-index` 高于表格，但展开行的 overflow 裁剪发生在渲染层面，z-index 无法突破

**修复（2 文件）**：

1. **VariantManager.vue** — `el-dialog` 添加三个关键 prop：
   - `append-to-body`：将弹窗 DOM 挂载到 `<body>` 下，脱离展开行的 overflow 裁剪范围
   - `:close-on-click-modal="false"`：防止误点遮罩关闭导致表单数据丢失
   - `destroy-on-close`：关闭时销毁 DOM，避免 body 下残留大量弹窗节点

2. **ProductCatalog.vue** — 展开行 overflow 放宽：
   - 新增 `:deep(.el-table__expanded-cell) { overflow: visible; }`，确保 VariantManager 组件本身的表格+按钮区域不被裁剪（虽然弹窗已挂到 body，但展开行内容本身也需要正常渲染）

**验证**：零 lint 错误。弹窗现在渲染在 body 层级，不再受表格展开行的 overflow 限制，可以完整展示表单+按钮。
