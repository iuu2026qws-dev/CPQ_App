2. **AttributeOptionManager.vue**：提前改为防御式 `Array.isArray(res) ? res : (res.rows ?? [])`
3. **ProductModel.vue**：不需改动——拦截器返回 `{ rows, total }` 直接匹配 `PageResult` 类型，`data.rows`/`data.total` 自然生效

## Snowflake ID 精度丢失修复（13:40）
### 根因
- Snowflake ID（如 `2064149007508221954`）超过 JavaScript `Number.MAX_SAFE_INTEGER`（9007199254740991），`Number()` 转换后丢失精度（误差2）
- 后端 `BigNumberSerializer` 已正确将 Long 序列化为 JSON string，但前端收到后又用 `Number()` 转回 number，精度丢失
- `QuoteDetail.vue` 第74行 `Number(route.params.id)` 导致传入错误的 quoteId，后端 `selectById` 返回 null，`store.currentQuote` 为 null，头部不渲染

### 修复方案（前端统一使用 string 类型传递 ID）
- **api/quoting.ts**：所有 ID 字段从 `number` 改为 `string`（quoteId/lineId/snapshotId/versionId/templateId/documentId/accountId/approvalChainId/parentLineId/modelId/sbomLineId/createdBy）
- **store/quote.ts**：所有函数参数 `id: number` 改为 `id: string`
- **QuoteDetail.vue**：`Number(route.params.id)` → `route.params.id as string`；`row.lineId as number` → `row.lineId as string`
- **QuoteVersion.vue**：同上；`versionId` 类型 `number|null` → `string|null`
- **TemplateSelector.vue**：`selectedId` 类型 `number|null` → `string|null`
- **SolutionCompare.vue**：`compareIds` 类型 `number[]` → `string[]`；去除 `Number()` 转换
- **vue-tsc**：修改后仅剩2个预存错误（ChannelPriceList/PriceBookList），与本次无关
- **E2E验证**：string ID 传递无精度丢失，详情接口正常返回数据

## 行项目添加失败修复（15:36-15:48）— 两个问题
### 问题1：line_number NOT NULL 无默认值
- 根因：前端未传 lineNumber，BeanUtil.toBean 后为 null，MyBatis-Plus 排除 null 字段 → INSERT SQL 无 line_number 列 → `Field 'line_number' doesn't have a default value`

- 同时自动设置默认 unit = 'PCS'

### 问题2：@TableLogic 值不匹配导致唯一键冲突
- 根因：`CpqQuoteLineItem.delFlag` 的 `@TableLogic` 使用默认值（0/1），但系统标准是 0/2（DDL注解「0正常 2删除」）

- 下次 SELECT MAX(line_number) 用 lambdaQuery() 只查 del_flag='0'，算出行号重复 → Duplicate entry
- **修复**：
  - `@TableLogic(value = "0", delval = "2")` 改为系统标准
  - `CpqQuoteLineItemMapper.selectMaxLineNumber()` 新增 @Select 注解方法直接查所有行（绕过 @TableLogic 过滤）
  - insert() 改用 baseMapper.selectMaxLineNumber()
