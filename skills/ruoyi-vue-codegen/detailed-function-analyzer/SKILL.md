# Detailed Function Analyzer

## Overview

将产品需求转化为完整的项目交付文档，包括功能需求文档、完整项目原型和开发需求文档。通过系统化的工作流程，确保从需求到实现的无缝衔接。特别针对 RuoYi-Vue 框架项目，提供符合 RuoYi 开发规范的完整开发文档。

## 工作流程

### 阶段 1: 功能需求分析

基于用户产品需求，详细分析并描述项目的各个功能模块：

1. **收集需求信息**
   - 理解用户的产品定位和核心目标
   - 明确目标用户群体和使用场景
   - 识别关键功能需求和非功能需求

2. **功能模块拆解**
   - 将产品需求拆分为具体的功能模块
   - 定义每个模块的职责和边界
   - 确定模块间的依赖关系

3. **编写功能需求文档**
   - 生成结构化的功能需求文档
   - 包含详细的功能描述、用户故事、验收标准
   - 保存至 `docs/` 目录，命名为 `功能需求文档.md`
   - 同步生成 HTML 格式，保存至 `docs/html/功能需求文档.html`

### 阶段 2: 完整原型设计

使用设计技能创建完整的项目可视化原型：

1. **设计原型**
   - 调用 `frontend-design`、`ui-ux-pro-max`、`canvas-design` 技能
   - 依据功能需求文档设计**完整项目原型**（不仅限于关键页面）
   - 确保原型覆盖所有功能模块和页面
   - 包括列表页、详情页、表单页、弹窗等所有交互界面

2. **原型交付**
   - 保存原型文件至 `prod/` 目录
   - 生成 HTML 格式的可交互原型，保存至 `prod/html/` 目录
   - 创建原型文件索引，包含所有原型文件的说明和链接
   - **重要：原型必须是完整的项目原型，不能只生成关键页面**

### 阶段 3: 开发需求文档

结合功能需求和完整原型，生成符合 RuoYi 规范的开发指导文档：

1. **分析技术实现**
   - 依据完整原型确定技术架构
   - 定义数据模型和接口规范
   - 标识技术难点和实现方案

2. **编写开发需求文档**
   - 生成详细的开发需求文档，包含以下内容：
     - **功能需求概述**：基于功能需求文档
     - **模块设计**：系统模块划分和职责
     - **接口设计**：RESTful API 接口规范
     - **数据库设计**：表结构、字段定义、索引设计
     - **RuoYi 开发规范要求**：
       - 工具类使用规范（Hutool 优先）
       - 项目结构规范
       - 前后端开发规范
       - 代码风格要求
   - 保存至 `docs/` 目录，命名为 `开发需求文档.md`
   - 同步生成 HTML 格式，保存至 `docs/html/开发需求文档.html`

3. **遵循 RuoYi-Vue 规范**
   - 使用 `ruoyi-developer-gen` 技能中的规范编写开发文档
   - 技术栈：Spring Boot 2.5.15 + MyBatis + Vue 2.x + Element UI
   - 工具类优先级：Hutool > RuoYi 工具类 > Apache Commons
   - 数据库表必须包含标准字段：`create_by`, `create_time`, `update_by`, `update_time`, `remark`, `del_flag`

### 阶段 4: 文档索引

生成统一的文档索引：

1. **创建索引文件**
   - 汇总所有生成的文档
   - 创建 HTML 格式的索引文件
   - 保存在与 `todo.md` 同级目录下，命名为 `index.html`

2. **索引内容**
   - 按文档类型分类（功能需求、原型、开发需求）
   - 提供清晰的文件路径和链接
   - 包含文档版本和更新说明

```

├── docs/

│   ├── 开发需求文档.md

├── prod/
│   ├── 原型资源/
│   │   ├── images/
│   │   ├── styles/
│   │   └── scripts/

│       ├── login.html
│       ├── dashboard.html
│       ├── module1-list.html
│       ├── module1-detail.html
│       ├── module1-form.html

│       └── ... (完整的项目原型页面)

```

## 执行原则

1. **顺序执行**: 严格按阶段顺序执行，确保后续阶段有充分的输入
2. **文档完整性**: 每个阶段必须生成完整的文档，确保信息无遗漏
3. **原型完整性**: **必须生成完整项目原型**，覆盖所有功能模块和页面，不能仅生成关键页面
4. **格式规范**: Markdown 文档需转换为 HTML 格式，便于浏览
5. **索引清晰**: 索引文件必须清晰反映所有交付物的位置和关系
6. **协作技能**: 灵活使用其他技能完成相应任务
7. **RuoYi 规范**: 开发需求文档必须遵循 `ruoyi-developer-gen` 技能中的规范

## 技能依赖

此技能需要调用以下技能：
- `frontend-design` - 前端界面设计
- `ui-ux-pro-max` - UI/UX 优化
- `canvas-design` - 视觉艺术设计
- `ruoyi-developer-gen` - RuoYi-Vue 开发规范（用于编写开发需求文档）

## 注意事项

1. 所有生成的 HTML 文件必须可独立运行
2. 索引文件应包含文档生成时间戳
3. 如目录不存在，应自动创建
4. 文档命名应清晰易懂，避免使用特殊字符
5. **完整原型要求**：原型必须包含项目的所有页面，包括但不限于：
   - 登录页面
   - 主页面/仪表板
   - 所有功能模块的列表页
   - 所有功能模块的详情页
   - 所有功能模块的表单页（新增/编辑）
   - 所有弹窗和对话框
   - 所有设置页面
   - 所有数据展示页面
6. 开发需求文档中的数据库设计必须遵循 RuoYi 规范，包含所有标准字段
7. 工具类使用必须遵循优先级：Hutool > RuoYi 工具类 > 其他
