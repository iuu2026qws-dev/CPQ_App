# 多步骤工作流设计模式

## 顺序工作流

### 模式：阶段式流水线
```
阶段 1: [输入] → 阶段 2: [处理] → 阶段 3: [输出]
```
适用于有明确依赖关系的任务。

### 示例：PDF 处理流程
```markdown
### 流程
1. 获取 PDF 文件路径
2. 使用 pdfplumber 提取文本
3. 按规则解析文本内容
4. 格式化输出结果
```

### 最佳实践
- 每个阶段检查输入是否满足要求
- 阶段失败时提供明确的错误信息和恢复指导
- 标注可并行的阶段

---

## 条件分支工作流

### 模式：If-Then-Else
```
条件 A → 分支 1
条件 B → 分支 2
其他   → 默认分支
```
适用于有多种处理方式但取决于输入类型的任务。

### 示例：文件格式处理
```markdown
### 文件处理流程
- **PDF 文件**：使用 pdfplumber 提取
- **Word 文件**：使用 python-docx 提取
- **图片文件**：使用 OCR 识别
- **其他格式**：提示用户转换格式
```

### 最佳实践
- 明确条件判断的优先级顺序
- 为每种分支提供完整的操作步骤
- 包含兜底分支（else/fallback）

---

## 可选步骤工作流

### 模式：核心 + 可选扩展
```
必做: [核心步骤]
选做: [增强步骤 1]
选做: [增强步骤 2]
```
适用于核心功能确定但有高级需求的场景。

### 示例：代码审查
```markdown
### 审查流程
**核心（必做）：**
1. 检查代码语法和格式
2. 检查逻辑正确性

**可选：**
- 优化性能建议（当用户要求时）
- 安全检查（当涉及敏感数据时）
- 文档更新建议（当 API 变更时）
```

### 最佳实践
- 用清晰的标签标注"必做"和"可选"
- 说明什么时候需要执行可选步骤
- 可选步骤的触发条件要具体明确

---

## 迭代工作流

### 模式：循环改进
```
生成 → 验证 → 发现问题 → 修复 → 生成 → ... → 满意 → 输出
```
适用于需要反复打磨的任务。

### 示例：代码生成
```markdown
### 生成流程
1. 生成初始代码
2. 运行测试验证
3. 如果测试失败：
   a. 分析失败原因
   b. 修复代码
   c. 回到步骤 2
4. 如果测试通过，输出最终代码
```

### 最佳实践
- 设置最大迭代次数避免无限循环
- 每次迭代记录改进内容
- 明确退出条件

---

## 多输出工作流

### 模式：一次输入，多种输出
```
输入 → 处理 → 输出 A（面向用户）
           → 输出 B（面向开发者）
           → 输出 C（面向管理者）
```
适用于同一内容需要不同形式输出的场景。

### 示例：API 文档生成
```markdown
### 输出物
1. **用户文档**：Markdown 格式，面向最终用户
2. **API 参考**：OpenAPI 规范，面向开发者
3. **变更摘要**：简要列表，面向 PM
```

### 最佳实践
- 明确每种输出的目标读者
- 标注不同输出的格式要求
- 确保输出之间的一致性
